# Part 1 — independent pipeline by OBLEMOS

This folder holds the Part 1 (developed market) work of team member **Oussama El Hadi (GitHub: OBLEMOS)**. It was built
separately from the main pipeline in `src/aiiaa/` and `scripts/`, which is the teammate's work. The scripts are kept
exactly as they were run, as a record.

## Files

| File | What it does |
|---|---|
| `First code.py` | Step 1 `prepare_data()`: EDA and data preparation, written to a `prepared/` folder. Step 2 `run_models()`: GLM, GAM, LightGBM and their blend, one submission per model |
| `Improved 1 code.py` | LightGBM fixed (init_score offset bug, integer-coded categoricals) and tuned by random search over 2 time folds |
| `Improved 2 code.py` | Honest validation (trees chosen on 2023, refit on 2021-2023, scored on untouched 2024); LightGBM without the weather variables (they identify the year); weighted blend |
| `Improved 3 code.py` | Claim-history leakage fix: `cust_claims_prev_1y` only counts claims reported before 1 January of the row's year; adds `cust_claims_prev_cal_year`; writes `prepared/improved3` |
| `Improved 4 code.py` | CatBoost (Tweedie 1.5, log-exposure + log-average baseline, own ordered target statistics for categoricals) added; `Blend4` = (GLM + GAM + LightGBM + CatBoost) / 4 |
| `blend_with_S09.py` | Blend test of `Blend4` with the team's Part 1 final S09 (see results) |
| `logs/` | Console output of each run |
| `submissions/part1_oblemos_improved4_Blend4.zip` | Best submission of this pipeline |

Each `Improved N` script imports `First code.py` and reuses its prepared data.

## Method summary

- **Data preparation** (`First code.py`, documented in its header):
  - exposure recomputed from the dates;
  - `sum_insured` values 1000 times too large divided by 1000;
  - construction codes unified (W/T mapped to timber);
  - motor `customer_id` zero-padded;
  - about 600 duplicate claims removed;
  - claims matched to policy rows by loss date;
  - repudiated claims excluded;
  - late-reported claims (IBNR) handled by shrinking the exposure with the reporting pattern;
  - each claim capped at the line's 99.5th percentile, with the excess added back as a loading;
  - `customer_service_contacts` dropped as leaky.
- **Models:**
  - GLM: Poisson frequency × Gamma severity, written as its own IRLS; numeric variables binned; forward selection on BIC by score test;
  - GAM: P-splines;
  - LightGBM (Tweedie);
  - CatBoost;
  - blends (equal and fitted weights).
- **Validation:** fit on 2021–2023, score on 2024 with Tweedie D² (power 1.5).

## Results (Kaggle Part 1)

| Submission | Public | Private |
|---|---|---|
| First code, Blend | 0.12592 | – |
| Improved 1: LightGBM / best single / Blend | 0.12272 / 0.12440 / 0.12742 | – |
| Improved 2: Blend_equal / Blend_weighted | 0.12735 / 0.12636 | – |
| Improved 3: Blend | 0.12758 | – |
| **Improved 4: Blend4** | 0.12736 | **0.13526** |
| Team final S09 (main pipeline) | 0.12863 | 0.13689 |
| 70% S09 + 30% Blend4 (late submission) | 0.12949 | **0.13718** |
| 50% S09 + 50% Blend4 (late submission) | 0.12971 | 0.13707 |

On its own, Blend4 scores slightly below S09 on the private board. Blended into S09 (at S09's level per line), it improves
both the private and the public score. The correlation of the two predictions is 0.965, so the two pipelines carry partly
different information. This is the reason it is being adapted to Part 2 as a blend component.

## Running

The scripts read the raw Part 1 data from a folder named `Data ptata` next to this folder's parent: `DATA = HERE.parent /
"Data ptata"` in `First code.py`. To rerun from the repository, point `DATA` at `data/iaa-ai-assisted-hackathon-2026-part-1`.
The prepared files (about 400 MB) and the per-model submission files are not versioned. They are regenerated by
`First code.py` (step 1 runs when `prepared/meta.json` is missing).
