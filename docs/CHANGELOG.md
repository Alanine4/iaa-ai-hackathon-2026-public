# Change log

Every change to data handling, code behaviour or modelling assumptions is recorded here.
Each entry: what changed, why, evidence, and where it lives in code (`file:function`).
Raw files in `data/` are never edited; all corrections are applied in code at load time.

| ID | Date | Area | Change | Why / evidence | Code |
|---|---|---|---|---|---|
| C000 | 2026-10-21 | repo | Initial repo: docs, profiling scripts, checklist | Baseline | `scripts/profile_data.py`, `scripts/check_quality.py` |
| C001 | 2026-10-21 | data (Q1) | `exposure` recomputed as (period_end − period_start + 1) / 365 on every row; stored value kept as `exposure_raw` | 5,723 motor / 4,176 buildings / 4,305 contents training rows disagree with their dates: value 365 (days instead of years), 1.0139 (370/365) and a 360-day basis. Claim frequency of these rows matches normal rows, so only the field is wrong. Test files have no mismatches. The data uses a 365-day year (2024 full-year rows end 2024-12-30). Evidence: `docs/investigate_q1_q3_q4.txt` | `src/aiiaa/clean.py:fix_exposure` |
| C002 | 2026-10-21 | data (Q2) | `customer_id` left-padded with zeros to 8 characters | 98,110 motor training and 25,554 motor test rows lost leading zeros; after padding 100% match `customers` | `src/aiiaa/clean.py:fix_customer_id` |
| C003 | 2026-10-21 | data (Q3) | `sum_insured` > 5,000,000 divided by 1,000; flag column `sum_insured_scaled` added | Buildings: genuine max 953k, scaled min 52m; same policies in other years differ by a median factor of exactly 1000; premiums equal to normal rows. | C005 | 2026-10-21 | target (Q5) | Claims whose loss date falls outside every row of their policy are excluded from the target and listed for audit | 294 motor, 67 buildings, 49 contents claims (mostly loss year 2020, before cover in the data). | C006 | 2026-10-21 | target | Reported cost developed to ultimate with a cost-weighted reporting-lag CDF per line (accident year 2021); per-row `completeness` = average CDF over the row's days; `claim_cost_ult` = reported / completeness, `exposure_eff` = exposure × completeness. Open-claim case estimates assumed unbiased | Single valuation snapshot, so no incurred triangle is possible. Motor 2024 pure premium 454 reported → 585 developed, in line with 2021–2023 (564–606). | C007 | 2026-10-21 | data / repo | Raw Kaggle files added to the private repository as a read-only backup, with SHA256 manifest, integrity tests and read-only file attributes; `*.parquet` marked binary in `.gitattributes`; `output/` (derived data) stays untracked | Team members need the same data; raw files must be provably unchanged. | C009 | 2026-10-21 | model | Per-line trend factor: exposure-weighted log-linear fit of developed pure premium by year, extrapolated from the weighted mean training year to the prediction year | Developed pure premium rises over 2021–2024 (buildings 384 → 481); pooled models predict an average year's level | `src/aiiaa/evaluate.py:trend_factor` |
| C010 | 2026-10-21 | model | Models fit claim cost per unit of completeness-weighted exposure (`claim_cost / exposure_eff`, weight `exposure_eff`), Tweedie power 1.5; three models: banded one-hot Tweedie GLM, LightGBM, XGBoost. Validation: train 2021–2023, validate 2024 on reported cost vs prediction × completeness; tree models early-stop on the validation year and are refit on 2021–2024 with 1.1 × best iterations. `year` is not a feature; level changes are handled by C009 | Same objective as the competition metric; avoids grossing up individual rows; keeps 2024 rows usable | `src/aiiaa/models.py`, `scripts/train_validate.py` |
| C011 | 2026-10-21 | model | GAM-style Tweedie model added: cubic B-splines with 8 quantile knots on numeric columns (median-imputed plus missing indicators), one-hot categories (min frequency 100), single L2 penalty | Requested by the team as an interpretable smooth alternative between the banded GLM and the tree models. Not an mgcv-style GAM: smoothness is set by one global penalty, not chosen per term | `src/aiiaa/models.py:GAM`, `tests/test_models.py` |
| C012 | 2026-10-21 | features (bug) | Object columns holding only True/False/None (buildings `smoke_alarms`) converted to float 1/0/NaN instead of category | XGBoost raised "Category index must contain only values of the same type ... Got values of type boolean" on buildings. Root cause: the object→category rule turned a boolean-with-missing column into a category with boolean levels. Only this column is affected (all object columns scanned) | `src/aiiaa/features.py:build_features`, `tests/test_features.py` |
| C013 | 2026-10-21 | model | Every model rescales its predictions so that total predicted cost equals total actual cost on its own training data | Diagnosis (`docs/diagnose_trees_motor.txt`, `docs/sweep_lgbm_motor.txt`): LightGBM starts balanced (0.988 after 1 tree) but ends at 0.83 of actual on its training rows; log-link Tweedie p=1.5 is not balance-preserving. Rebalancing raised motor validation D2 from 0.066 to 0.073. Uses training data only | `src/aiiaa/models.py:Balanced` |
| C014 | 2026-10-21 | target / model | Large-loss capping: each claim capped at the 99.5th percentile of the line's non-repudiated net claim costs (motor 51,585; buildings 147,445; contents 28,449); models learn capped cost; the capped excess is spread back with a per-line load factor (total / capped cost over the training years) | Motor sweep: cap 50k improved validation D2 for every tree setting (best 0.0812 vs 0.0763 uncapped). Capped share of cost: motor 8.8%, buildings 4.2%, contents 2.1%. The load is uniform, so large-loss propensity is not differentiated by risk | `src/aiiaa/target.py:large_loss_cap,row_target`, `scripts/build_target.py`, `scripts/train_validate.py` |
| C015 | 2026-10-21 | model | Tree defaults simplified: LightGBM 7 leaves, min 3000 rows per leaf (was 63 / 200); XGBoost depth 3 (was 6); max 5000 rounds with early stopping | Deep trees early-stopped after ~50 rounds and scored lower; motor sweep best was 7 leaves / 3000 rows (D2 0.0812). XGBoost depth chosen to match, not separately swept | `src/aiiaa/models.py:LGBM,XGB` |
| C016 | 2026-10-21 | submission | Trend-share variants of the blend built by rescaling saved test predictions (no retraining): no trend (share 0, mean 330.0) and half trend (share 0.5, i.e. square root of the factor, mean 346.1); full trend S01 mean 363.3 | Validation predictions were 5-21% above actual with the trend and near actual without it; the public leaderboard decides the trend share. Files kept in `work/` (untracked) | `scripts/make_trend_variants.py` |
| C017 | 2026-10-21 | model tuning | Tree hyper-parameters can be overridden (`models.make(name, **params)` merges with defaults). Time-based CV tuning script: expanding-window folds 2021-22→2023 and 2021-23→2024, configurations ranked by mean level-calibrated D2 (`d2_cal`) so ranking quality is tuned separately from the overall level (trend share, C016). Search: LightGBM default + 12 random, XGBoost default + 6 random, GLM n_bins 5/10/20 + higher alpha, GAM n_knots 5/8/12 + higher alpha | Single-year validation is noisy and the 2024 fold already shaped C014/C015 | `src/aiiaa/models.py`, `scripts/tune_cv.py`, `docs/cv_trees.md`, `docs/cv_linear.md` |
| C018 | 2026-10-21 | model tuning | Per-line tuned hyper-parameters (`src/aiiaa/params.py`) used by the pipeline for both the validation fit and the full refit. Adopted: motor LightGBM (15 leaves, min 6000 rows, lr 0.03, colsample 0.5, subsample 0.7, lambda 10), motor XGBoost (depth 2, min_child_weight 1000, lr 0.03, colsample 0.5, subsample 0.9, lambda 0), contents XGBoost (depth 2, min_child_weight 50, lr 0.03, colsample 0.8, subsample 0.7, lambda 0).
